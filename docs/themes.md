# 오하루 테마

설정 > 화면 > 테마에서 기본, 숲의 아침, 로즈 가든, 푸른 바다, 라벤더 오후, 모래와 햇살, 민트 한 잔, 복숭아빛, 차분한 잉크, 레몬 정원을 선택합니다. 기존 화면 구성과 크기는 변경하지 않습니다. 기본 선택은 기존 색상 CSS를 그대로 복원합니다. 기존 기본 디자인의 보조 글자 대비는 변경하지 않았으므로 기존 디자인 전체가 WCAG AA라는 의미는 아닙니다.

## 나만의 테마

AI로 나만의 테마 만들기에서 요청문 복사 → ChatGPT/Claude 열기 → 원하는 분위기를 덧붙여 붙여 넣기 → 결과 JSON 붙여 넣기 또는 파일 선택 → 검사하고 미리 보기 → 미리 본 테마 적용 순서입니다. 미리 보기는 고정 예시만 사용합니다. 적용 후 이전 테마로 되돌릴 수 있습니다. 기본으로 복원은 항상 사용할 수 있습니다. JSON 내보내기는 복사 가능한 JSON을 표시합니다. 기본 내보내기는 접근성을 보완한 색상이며 그대로 가져오면 원래 기본과 보조 색상이 조금 다릅니다.

이 경로는 로그인 권한이나 API 키를 Oharu에 전달하지 않습니다. 외부 AI에는 사용자가 붙여 넣은 요청문만 전달됩니다. 구독을 API 크레딧으로 취급하지 않습니다. MCP의 기존 할 일 접근 권한도 테마 제작 때문에 추가하지 않습니다. 테마 MCP/API를 향후 추가할 때도 `OharuThemes.validate`와 동일한 스키마와 대비 검사를 서버에서 재사용해야 합니다. 현재 새 원격 테마 API/MCP 도구는 제공하지 않습니다.

## 저장과 기기 일관성

게스트는 이 브라우저에 저장합니다. 로그인하면 계정별 로컬 저장과 Supabase `user_metadata.oharu_theme_v1`에 저장합니다. 다른 기기는 열기/포커스 복귀 때 서버 설정을 읽습니다. 동시에 변경하면 서버에 마지막으로 저장한 값이 우선합니다. 온라인 저장이 실패하면 이 기기에서 유지하고 오류를 표시합니다. 연결 복구 후 다시 선택해야 계정에 재저장됩니다. 다른 기기의 실시간 구독이나 오프라인 자동 병합은 제공하지 않습니다. 로그아웃하면 게스트 테마로 돌아갑니다. 저장 공간 거부 시 현재 화면만 적용됩니다. DB 테이블 변경은 없습니다.

## 안전한 ThemeV1

루트 키는 `version`(1), `name`(1~40자), `tokens`만 허용합니다. tokens는 `bg`, `card`, `text`, `muted`, `accent`, `soft`, `line`, `danger`, `dangerSoft` 9개이며 모두 `#RRGGBB`만 가능합니다. 파일 최대 8KB, 문자열 최대 8192자입니다. URL, 이미지, CSS, JS, HTML, 레이아웃 토큰, 추가 키는 거부합니다. 이름은 HTML로 해석하지 않습니다.

본문/보조 글자와 배경/카드, 강조색과 배경/카드/연한 강조 배경, 위험색과 카드/위험 배경, 흰 버튼 글자와 강조색 모두 4.5:1 이상을 검사합니다. 가져오기, 저장, 로컬 복원, 계정 복원에 동일 검증을 적용합니다. 투명 창에서는 실제 바탕화면 색이 합성되므로 이 대비 수치를 보장하려면 배경 불투명도를 100%로 두어야 합니다.

새 테마의 체크박스·입력·선택 상자 경계는 `muted`, 선택 상태는 `accent`, 키보드 포커스는 `text` 색상을 사용합니다. 각 색은 카드와 바탕에 3:1 이상의 비텍스트 대비를 충족합니다. 연한 `line` 토큰은 장식 구분선에만 사용하며 조작 경계로 쓰지 않습니다. 토글의 꺼짐 상태도 `muted`로 구분합니다. 모든 기존 요소 수정은 비기본 테마에만 한정되고 크기·배치·글꼴은 변경하지 않습니다.

## 통합 및 검증

`theme-system.css`와 classic script `theme-system.js`를 기본 스타일 뒤에 로드합니다. 스크립트가 `#setDesign`에 설정 UI를 추가합니다. Supabase 생성 후 `window.OharuThemes?.connect(supabase)`를 한 번 호출합니다. 모바일 번들에도 두 파일과 호출을 포함해야 합니다. 게스트 기능은 서버 연결 없이 동작합니다.

자동 검증: `node --test tests/theme-system.test.cjs`. 테스트는 10종 대비, 악성/잘못된 JSON, 저장 거부, 복원, 계정 분리, 동기화 실패를 포함합니다. 웹/모바일/Electron 실제 화면의 레이아웃·스크린리더·기기간 서버 왕복 검증은 통합 담당자의 별도 결과를 확인해야 합니다. 실제 배포/실기기 검증을 이 문서만으로 통과 처리하지 않습니다.

## 외부 제작 도구용 인터페이스

현재 구현된 인터페이스는 공개 정적 스키마 파일 `web/theme-schema.json`과 브라우저의 `window.OharuThemes.validate(jsonOrObject)`, `window.OharuThemes.exportTheme()`입니다. 웹 배포에 포함하면 스키마 경로는 `/theme-schema.json`입니다. 실제 배포 성공과 공개 URL 응답 확인은 배포 담당 결과를 따릅니다. 스키마 조회에는 인증이나 사용자의 할 일 접근이 필요하지 않습니다.

스키마는 JSON Schema draft 2020-12이며 필드와 색상 형식을 정의합니다. JSON Schema만 통과했다고 적용 가능한 테마는 아닙니다. `validate`의 명시된 색상 대비 검사와 크기 제한도 반드시 통과해야 합니다. 이름은 JSON Schema의 40 Unicode 문자 제한과 별개로 현재 JS 검증기에서 UTF-16 코드 단위 40자 제한을 추가 적용합니다. 이모지는 두 단위가 될 수 있습니다. 파일은 8192바이트, 문자열 입력은 8192 UTF-16 단위로 제한합니다.

```js
// 테마 제작 도구의 결과를 검사하고 전달하기 위한 공개 브라우저 인터페이스.
// validate는 화면이나 계정 설정을 변경하지 않는다.
const draft = window.OharuThemes.validate(generatedThemeJSON);
const jsonForUserImport = JSON.stringify(draft, null, 2);
const exportedCurrentTheme = window.OharuThemes.exportTheme();
```

외부 제작 도구는 스키마에 맞춘 JSON을 사용자에게 제공합니다. 사용자는 설정의 가져오기에서 고정 샘플을 미리 보고 **미리 본 테마 적용**을 직접 누릅니다. 임의 사이트의 `postMessage`, 쿼리 파라미터, URL 테마 자동 다운로드/적용, 원격 스크립트 실행을 수신하는 경로는 구현하지 않습니다. `save`, `apply`, `connect`는 Oharu 내부 UI/인증 통합용이며 외부 호출 서비스나 권한 부여 인터페이스가 아닙니다.

### 향후 REST/MCP 계약 초안 — 미구현·미배포

| 인터페이스 초안 | 입력 | 성공 결과 | 허용하지 않는 동작 |
| --- | --- | --- | --- |
| `POST /api/theme-drafts/validate` | ThemeV1 JSON, 최대 8192바이트 | 검증된 `theme`, 대비 검사 결과, `status: "draft"` | 프로필 저장, 테마 자동 적용, URL 가져오기 |
| MCP `validate_theme_draft` | 동일 ThemeV1 JSON | 동일한 draft 및 대비 결과 | 할 일 읽기, 계정 수정, 토큰 발급 |

두 인터페이스를 실제 제공할 때는 별도 구현과 출시 검증이 필요합니다. 서버의 공통 검증 모듈은 현재 `validate`와 동일한 키 허용 목록·버전·대비 규칙을 사용해야 합니다. 구조/대비 오류는 `422`와 필드별 오류로 반환하고, 크기 초과는 `413`, 인증 실패는 `401`, 권한 부족은 `403`, 요청 제한은 `429`로 구분합니다. 예시 응답은 `{ "status": "draft", "theme": { ... }, "checks": { "contrastPassed": true } }`입니다. 이 응답은 테마 적용 승인이 아닙니다.

인증이 필요한 제작/초안 저장 기능으로 확장할 경우 기존 사용자 세션의 본인 범위에서 최소 권한을 별도로 설계하고, 인증 및 요청 제한을 서버에서 검사합니다. 기존 MCP의 할 일 권한을 테마 권한으로 암묵 확대하지 않습니다. 클라이언트나 외부 모델에 서비스 역할 키를 전달하거나 제3자 구독 토큰을 수집하지 않습니다. 기존 사용자 데이터나 계정 ID를 요청문에 자동 포함하지 않습니다. 토큰 발급·OAuth 연결·지속 권한 확대는 실제 승인과 보안 검증을 거쳐야 합니다. 현재 초안 검증을 위해 그런 권한을 발급하지 않았습니다.
