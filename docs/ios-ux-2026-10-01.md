# iOS 사용성 보강 — 2026-10-01

기존 iOS SafeAreaProvider/SafeAreaView와 하단 메뉴를 유지했다. HTML에 별도 safe-area inset을 더하지 않았으며 Android/웹 화면 구조는 변경하지 않았다. Expo SDK57 공식 문서(https://docs.expo.dev/versions/v57.0.0/)를 확인했다.

## 수정

- iOS 화면 이동을 동일 문서 history에 등록했다. 설정의 뒤로가기, 로그인 닫기, Escape와 history back이 같은 이전 화면으로 돌아간다. 이전 달력 월/선택일, 스크롤 및 접근성 포커스를 복원한다.
- 로그인 닫기를 폼 아래 링크에서 상단 sticky 버튼으로 옮겼다. 닫을 때 키보드 포커스를 해제하고 비밀번호를 비운다. 입력 중이던 게스트 할 일은 보존한다. 이미 전송한 서버 로그인 요청을 취소하는 기능은 아니다.
- 인증 이후 이전 history의 로그인 화면이 재노출되지 않도록 실제 현재 인증 상태를 검사한다. history에는 계정/토큰/할 일 본문을 저장하지 않는다.
- 키보드 표시·visual viewport 변경 시 포커스 입력칸을 스크롤한다. 앱 복귀 시 키보드 상태를 다시 동기화한다.
- React Native fontScale을 iOS HTML에 전달했다. 제목, 버튼, 입력칸, 할 일 본문/시간, 달력 날짜 등 주요 텍스트가 확대된다. 작은 설정 보조 라벨과 일부 장식은 기존 크기를 유지한다. 큰 텍스트에서는 메뉴/설정 행이 줄바꿈되고 본문 영역은 스크롤된다.

## 실제 수행한 검증

`node --test mobile/ios-ux.test.cjs mobile/bootstrap.test.cjs`: **10/10 PASS**. Chromium에서 실제 bundled HTML을 실행하고 외부 요청을 차단했다.

- Android/iOS 게스트 첫 실행, 두 항목 저장/재실행.
- 설정→이전 달력 월 복원, history back/forward.
- 높이330 로그인 화면에서 닫기, Escape, 비밀번호 제거, 포커스 복원.
- 실제 설정 scrollTop150 복원 및 미제출 게스트 입력 보존.
- synthetic 인증 상태 경계에서 과거 로그인 route 차단/로그아웃 상태 재접근. 실제 계정 인증을 수행한 테스트가 아니다.
- 320폭/가로 화면 및 200% 텍스트: 입력32px, 할 일 본문31px, 시간24px, 달력 날짜26px 확인. 달력 내부 가로 넘침 없음, 메뉴가 viewport 아래로 벗어나지 않음.
- Android는 iOS 메뉴/history 변경 없음.

App.js는 Babel JSX 구문 검사도 통과했다. 새 EAS 빌드/배포/자격 발급은 수행하지 않았다.

## 화면 증거와 미검증

`mobile/validation/ios-ux-browser-home.png`, `ios-ux-browser-short-login.png`, `ios-ux-browser-large-text.png`는 **Chromium 브라우저 모사 화면**이다. 실제 iPhone/WKWebView 스크린샷이 아니다. 짧은 로그인 캡처는 키보드 자체를 합성한 화면이 아니라 viewport 높이를 줄인 화면이다.

Mac/iOS simulator/실제 iPhone이 없어 네이티브 edge-swipe 인식, interactive keyboard dismissal/IME, 노치·홈 인디케이터의 실제 inset, VoiceOver, 실제 이메일 로그인·외부 인증 복귀는 검증하지 못했다. history 이벤트 검증을 실제 손가락 스와이프 통과로 해석하면 안 된다. 파일 선택기·시스템 권한 모달의 취소/복귀도 실제 iOS에서 추가 확인해야 한다.
